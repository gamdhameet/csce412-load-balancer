Design document

Load balancer simulation

Two request types, two server pools, one clock. Requests move through an IP filter before they enter a queue.

System flow

Figure 1

The configuration supplies task lengths, arrival probability, scaling interval, and blocked IP ranges. The generator creates requests with source and destination addresses, a duration, and a P or S job type. The filter rejects blocked source addresses. The switch sends the remaining requests to the matching queue. On each clock cycle, active servers advance their work and idle servers take the oldest queued request. Both pools contribute to the final report.

Scaling rule

Checked every 100 cycles by default
Queue depthAction for that pool
Below 50 × server countRemove one idle server, down to the configured minimum.
50–80 × server countKeep the current server count.
Above 80 × server countAdd one server, up to the configured maximum.
